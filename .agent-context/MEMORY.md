# Shared Agent Memory & Decisions

Record architectural decisions, library quirks, solved bugs, and conventions here so no agent repeats a solved mistake.

- **[Init]** All subagents must read `AGENTS.md`, `ARCHITECTURE.md`, `MEMORY.md`, and `PROGRESS.md` before executing.
- **[Tooling]** `codex exec` hangs on "Reading additional input from stdin" unless stdin is redirected (`< /dev/null`).
- **[Tooling]** `agy -p` headless auto-denies its `command` tool unless `~/.gemini/antigravity-cli/settings.json` has `"toolPermission": "always-proceed"`; allow-rules alone were not enough. Never use `--dangerously-skip-permissions`.
- **[Tooling]** Dev server port 5173 may be held by another session; `.claude/launch.json` has `vite-5174` (auto-moves to a free port).
- **[Process]** Baseline trick: orchestrator `git add -A` after verifying a phase, so the next worker's changes show as unstaged `git diff`. Nothing is committed to master without the user.
- **[Process]** Worktrees need a commit base; R3 used branch `r3-visuals` with a snapshot commit, merged back as a patch (`git diff <snapshot>` excluding contract files) instead of a branch merge.
- **[Design]** Structures are generic `TargetRef {kind:'structure', id}`; the checkpoint gate stays its own special case. Visuals must derive landmark geometry from `layout.structures` + tagged colliders — never literal coordinates or structure ids (R3 fix round).
- **[Design]** Victory = gate destroyed AND all `post==='checkpoint'` humans DEAD. Civilians/barricade soldiers don't block victory.
- **[Design]** Momentum: only `MomentumSystem` mutates `state.momentum`; multipliers read live. Start followers give no momentum.
- **[Bug]** Tests that clear `state.zombies` must also reset `followerCount` (5 start followers exist now).
- **[Tests]** Long full-world sims (opening autopilot, 5400 steps) need ≥ 30 s timeout under parallel suite load; perf assertions belong in the dedicated stress test.
- **[Persistence]** `applySave` only triggers `navGrid.rebuild()` + `crawlNavGrid.rebuild()` when a structure or gate transitions from intact/enabled to destroyed/disabled, keeping repeated `applySave` calls idempotent (including `navGrid.version`). `encodeBits`/`decodeBits` use a pure lookup-table Base64 implementation (no `Buffer`/`btoa`) and normalize `DiscoveryState.bits` to `0 | 1` with a full `revealed` recount on load.

- **[T003 Navigation]** `NavigationGrid.buildFlowField(goals, reuse?, maxDistance?)` bounds path cost in meters (not Euclidean radius); omitted remains unbounded. Whole-array resets prevent stale distance/direction/goal indices on reuse. Cached legal adjacency + visited-cell direction generation: 320x256 cells / 1024 colliders / 140 m bound averaged 5.46 ms over 20 standalone builds (18.99 ms under full suite load; CI assertion <25 ms).
- **[T003 Gate access]** A distant explicit attack/squad order uses max(nav.flowFieldMaxDistance, leader-to-target distance + 60). Gate redirects must test outside access with that attack bound; the shorter follow field may legitimately report a distant gate unreachable.
- **[T003 Collision]** Existing 8 m CollisionWorld broad phase and reusable query output arrays are adequate at 1536 colliders: 20000 local queries took 16.25 ms standalone; no CollisionWorld changes needed.
- **[T003 -> T007 follow-up]** HordeSystem ignores false from followField.sample in its far/regroup and blocked-follow branches (around lines 573-579). Out-of-bound samples zero steering; existing speed catch-up alone cannot move those stragglers. T007 owner must add direct fallback/catch-up behavior (and any planned offscreen teleport); T003 brief explicitly forbade editing HordeSystem. See reports/T003-codex.md.
- **[T002 World]** `buildDistrictLayout(seed?)` now generates the full 400 x 320 m world; `Simulation()` still defaults to the untouched legacy layout. Four free ambient budgets total 96; bus/alley/pen add 45 held zombies; humans total 86. Structure ids: 1 bus, 2 alley, 3 store, 4 suburban pen, 5 station door, 6 mall shutter. Start nest is `nest_start`; capture nests are `nest_<strongholdId>`.
- **[T002 Queries/streaming]** `worldQueries.ts` takes layout first for every query. Chunk ids are row-major from NW (0) to SE (19); district seam ownership is east/south (x=0,z=0 is shopping), and district/chunk point queries clamp outside bounds. Radius queries use circle/rectangle overlap. ChunkStreamer uses configured 150/190 m radii plus the brief's hard 12-chunk budget, prioritizing the containing/nearest chunks when radii cover more than 12; budget eviction can precede the unload radius.
- **[T002 Geometry/T010]** Hollow landmark shells are authored from StructureDef enclosures, with unique tags `<landmark>-<id>-{n,e,w,s,sw,se,wn,ws,door}` as applicable; derive visuals from data rather than old literal landmark tags/coordinates. Industrial checkpoint is translated (+80,-60) from legacy. Tower humans are on inward platform edges (W x=147.6, E x=178.4, z=-115.5), 0.6 m beyond their blocking 3 x 3 m supports so every human spawn is ground-query walkable. T010 should extend platform decks to at least 4.2 m width to cover these positions; keep support colliders unchanged.
- **[T002 Verification]** `tests/world.test.ts` verifies every nav cell is exterior-connected except sealed interiors; after all six doors and the industrial gate open, no walkable islands remain. Whole spawn rectangles, all guard waypoints, entrances, nests, reinforcement LOS and twelve seam crossings are checked, plus a 120-step open-world simulation and bounded streaming loops.

- **[T005 Progression]** ProgressionSystem now owns atomic ability eligibility/spend/cooldowns, capture-driven unlock helpers, and nest-only loadout changes. Innate abilities are always unlocked; moving a slotted ability preserves its cooldown. Pounce remains data-only and activation is denied as locked even if manually unlocked.
- **[T005 -> T007/T012]** Call `updateProgression(ctx, dt, input)` once before leader/horde/combat updates (T012 wiring). Existing timers advance before new slot activations, giving Frenzy its full configured duration. `hordeSpeedMultiplier` / `hordeAttackRateMultiplier` expose the active global Frenzy multipliers; per-follower activation-radius filtering belongs to HordeSystem, using the `frenzyStart {pos, radius}` snapshot.
- **[T005 Brutes]** Evolution selects nearest living, non-dormant, non-brute followers (entity id breaks equal-distance ties), spends only for actual conversions, and counts all living brutes against the cap. `evolveToBrute(z)` is idempotent: repeating it neither heals nor compounds speedScale. Death frees brute capacity; followerCount is unchanged by evolution.

- **[T004 Alpha combat]** `updateLeader` owns edge-triggered windup/recovery/combo timing and calls `resolveLeaderAttack` at impact. `updateCombat` no longer auto-melees for the leader. `aimLeaderAttack` locks a reachable target at swing start (nearest living human in the aim cone, otherwise nearest gate/structure face); impact rechecks reach/cover. Input `attack` is already a one-step edge; there is no extra button latch or buffered recovery press.
- **[T004 Damage attribution]** `damageGuard(ctx, guard, amount, source, byAlpha = false)` preserves existing callers. Only a lethal zombie-source hit with `byAlpha=true` sets `killedByAlpha`; that pending conversion uses `alpha.infectChance`. Nonlethal Alpha damage never guarantees a later horde kill. Kill/infect biomass is awarded once in `damageGuard`; convert biomass once when a rising zombie joins the horde.
- **[T004 -> T008 stagger]** A surviving target of claw combo hit 3 receives `staggerTime = BALANCE.alpha.staggerTime`. T008 must tick it and suppress human movement/shooting; HumanAISystem was outside T004's scope. Large hits cancel Alpha swings/combos and immediately stop movement for hit stun.
- **[T004 tests/integration]** Explicit leader attacks replace automatic melee in `tests/combat.test.ts` and the permitted minimal extra edit in `tests/structures.test.ts`. `tests/alphaCombat.test.ts` adds 23 combat/modifier tests. Combat/conversion accept `respawning` so those systems can continue when T012 wires the new step order; dormant agents are skipped. Final T004 verification: tsc clean, 30 files / 292 tests passing.
